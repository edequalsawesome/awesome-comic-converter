# Reliable comic conversion implementation plan

Goal: make the existing browser app useful for a backlog of AZW3 comics, with complete batches, trustworthy metadata, visible/changeable covers and safe exports. User explicitly authorized implementation after the audit; no additional design permission required.

Architecture: retain vanilla JavaScript and existing parser/controller/worker files. Normalize every input into per-book jobs, process sequentially, and use one archive writer. Keep source File references and a compact image manifest for cover changes; re-read on changes rather than retaining all source ArrayBuffers. Keep image bytes unchanged. Browser app is the deliverable; label the separate Calibre prototype unsupported rather than claiming to repair that independent application.

Spec/evidence: previous audit at main 502fec880804d956cbbe3ea7a92abb1fe643a815. Twelve Desktop All-Star Superman files contain 281 resources including 12 EXTH thumbnails and one 48x48 icon; expected default output 268 images total. All first images are correct covers. EXTH 201=202 for eleven books, including error placeholders for #4/#7/#9. Samples have readable images but encryption field 2, so do not reject these files solely by the text-encryption flag, attempt decryption, or claim full text/reading-order reconstruction.

Measured source total is 84,265,728 bytes (80.36MiB), comfortably below the retained budget. Per-issue expected output counts (#1..12): 22,21,23,22,23,22,22,23,22,22,23,23. Expected first-cover record indexes: 40,41,43,44,46,43,39,43,40,44,41,43. EXTH201/202 relative offsets: 22/22,21/21,23/23,22/22,23/23,22/22,22/22,23/23,22/22,22/22,0/25,23/23. In #11 the distinct cover is already the first resource; retain distinct valid EXTH preference for other files, with visible preview and user override.

Flow: FileList/drop -> normalized snapshot -> directory-aware per-AZW3 jobs -> validated records/EXTH -> image candidates -> cover/filter policy -> shared CBZ writer -> cover preview + editable choices -> unique download or folder save.

## 1. Parser and executable checks

Files: azw3-parser.js, security-utils.js, tests/converter.test.cjs, package.json; use Node built-in test/assert/vm, no test framework. Add a lint script using syntax checks (and label it syntax validation, not a comprehensive style linter).

- Write a synthetic Palm/MOBI fixture that places real fields at record+108/+128 and sentinel wrong fields at record+124/+144. Assert correct first-image index/EXTH and title/author/publisher. Assert truncated tables, out-of-file/overlapping offsets and malformed EXTH lengths reject safely. Existing code should fail before repair.
- Validate record directory fits and offsets strictly increase from after the directory to within buffer. Read 24-bit IDs as three bytes. Validate PalmDOC/MOBI fields against first record end and declared header length. Correct image/EXTH offsets. EXTH iteration bounded by header, length, count and record end, with clear errors for malformed declarations. Treat 0xffffffff first-image as no declared images; never scan arbitrary invalid ranges.
- Decode embedded title (EXTH 503 then MOBI title offset/length), repeated author 100, publisher 101, description 103, date 106, language 524; EXTH201/202 are relative resource indexes. Resolve using first image index. Keep author and creator aligned. No EXTH values means filename fallback in controller. Infer series/index only for explicit title '#number' pattern; OPF remains authoritative where supplied.
- Extract valid JPEG/PNG/GIF resources without reencoding, preserve physical order, retain recordIndex/dimensions/format; ensure filenames renumber selected pages sequentially with consistent width of at least 4 digits.
- Default omit designated thumbnail unless there is no other usable image. A shared cover/thumbnail designation does not exempt it. Explicit user cover choice overrides default exclusion for that one resource. Ignore automatic cover pointer if it equals thumbnail or points to a tiny placeholder. Prefer a valid distinct cover, otherwise first non-thumbnail/non-tiny image. Tiny ancillary heuristic: <=64x64 only when larger page images exist. Document with ponytail comment and expose 'Include thumbnails and small images' per result so no permanently lost resources. Never apply broad size thresholds to all pages. Make warnings honest: resource order fallback, not verified logical page order. Reject unrecognized/unsupported image-only outcomes clearly.
- Tests cover thumbnail=cover placeholder, distinct cover at later record, only one image, tiny true-only image, restoring excluded resources, no null-buffer double exception, byte preservation and >999 filename sorting.

## 2. Unified batch intake and archive/export path

Files: app.js, opf-parser.js, zip-worker.js, security-utils.js, index.html.

- Normalize native FileList immediately via Array.from; clear both input values after snapshot. Drop API calls collect entries/files synchronously while access remains valid. Reuse existing traversal but fix synthetic paths (full parent path), fallback all files, and handler routing.
- One active operation guard covers file/folder/drop intake, clear, cover rebuild and bulk export. Disable relevant controls and also guard methods, release in finally; second intake gives a persistent message, never clears running results. Keep sequential processing.
- Filter irrelevant folder entries before validation; count AZW3 jobs, not sidecars, for batch limit. Validate per-book file size/signature and fail only that book; retain batch total bound. Every AZW3 becomes a job. With one AZW3 in directory, exact metadata.opf and exact cover.jpg/jpeg/png/gif sidecars allowed (no backcover substring). Multiple AZW3 siblings only use same-stem OPF/cover associations; ambiguous shared sidecars produce warning and books still convert. Bound OPF read to 1MiB before text load; sidecar images validate signature before use.
- Unify createCBZ/createEnhancedCBZ around shared worker action with ComicInfo.xml for all outputs. Always renumber actual selected page list; selected cover first and exactly once. External sidecar may be explicit cover option; never delete a different embedded page based only on matching dimensions. Mark ComicInfo page Image=0 Type=FrontCover; PageCount equals images actually written. Metadata.json retained for diagnostics.
- OPF: content attributes for Calibre series/index, namespace-safe DC lookup, only merge actual nonempty supplied metadata on valid OPF, preserve embedded values on invalid OPF with warning. Calendar components from validated ISO date, no local-zone drift/NaN. XML escaping remains.
- Worker local JSZip import, onerror/onmessageerror rejects all callbacks and disables worker. Constructor failure -> existing fallback. Do not impose arbitrary short timeouts on legitimate large ZIP work. Reuse one worker archive implementation where feasible, keep fallback semantics identical and test both. Avoid transfer detachment breaking fallback; Blob payloads or retained original views are acceptable, no per-page cloning of whole source buffers.
- Unique sanitized output names assigned once and reused by all download modes; case-insensitive collision checks with numbered suffixes. Direct folder save checks existing paths and picks unused suffixes (including case-insensitive directory contents); no overwrites. Preserve partial-save counts and filenames in persistent status; cancellation is neutral. Disable exports/rebuild while pending operation. Blob URLs revoked on replacement/reset.
- Keep realistic file/batch/output limits; remove false claims that existing counter bounds browser memory. Enforce retained-output budget before accepting more results (e.g. 512MiB), surface save/clear advice without silently losing completed results. Don't parallelize conversion.
